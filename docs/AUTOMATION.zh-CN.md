# 主页自动更新

[English](AUTOMATION.md) · [简体中文](AUTOMATION.zh-CN.md) · [主页](../README.zh-CN.md)

## 1. 自动更新的内容

GitHub Actions 工作流分页读取账号的全部公开仓库，刷新 `README.md`、`README.en.md` 和 `README.zh-CN.md` 中的四个标记区域：

| 区域 | 内容 |
| --- | --- |
| `ABOUT` | 根据当前项目方向生成经历概要，不列项目链接或数量 |
| `PORTFOLIO` | 全部符合条件的项目、方向及仓库简介 |
| `PROJECTS` | 按创建时间排列的最新三个项目，名称与语言分列对齐 |
| `TECH_STACK` | 根据公开仓库元数据、语言清单和 README 检测的技术徽章，每行最多四个并禁止行内换行 |

概览与目录排除私有、归档、Fork、其他账号所有的仓库及主页仓库。无法匹配既有分类的新方向仍会出现在**其他工具与资料**中。分类依据仓库名称、简介和 Topics，表示项目涉及的方向，不代表个人资历。一个项目采用首次匹配的分类，跨领域项目也只列一次。仓库简介在中英文版本中均保留原文。

主页保留原来的双栏布局：左侧为介绍、技术栈和联系方式，右上为统计卡片，右下为最近项目。完整项目目录与协作说明放在下方的折叠区域。问候标题、联系方式和团队协作链接由人工维护。About Me 突出工程方式与项目经历，不作为仓库索引。技术徽章表示源码资料中的技术线索，不代表熟练程度或硬件支持已经验证。方向分类不读取 README 全文，避免把资料库引用的技术误当成作者的实现经验。

## 2. 更新时机

现有定时配置在**北京时间每天 09:17**（UTC `01:17`）请求运行，GitHub 可能延迟调度。新建其他仓库不会立即触发主页工作流，会在下一次定时运行时纳入；仓库所有者也可在 Actions 中手动运行 **Update profile introduction and projects**。

`main` 上修改更新脚本、测试、工作流或任意一份 README 时也会触发。工作流先执行回归测试，再生成内容。更新后的工作流与全部 README 必须发布到默认分支后，新行为才会生效。

只需内置 `GITHUB_TOKEN` 对主页仓库的写权限，无需个人令牌、私有项目访问权限或外部 AI 服务。自动提交修改默认分支的 README，不修改账号侧栏的短 **Bio**。

## 3. 维护与故障处理

每份 README 中，各区域必须各有一对顺序正确且唯一的 `START` / `END` 标记。标记之外的内容保留。生成区域会在下次运行时覆盖；需要调整项目介绍时，应修改对应仓库的简介、Topics，或 `scripts/update-projects.cjs` 中的分类规则。

本地检查：

```bash
node --test tests/update-projects.test.cjs
```

脚本先获取输入并校验全部文档，再开始写入。源项目没有 README 可以继续，其他 API 错误会终止运行。主页标记缺失或格式错误时，不写入任何文件。相同输入生成相同内容，不产生重复提交。每个文件更新时校验原 SHA；三个文件顺序写入，并非单次原子事务。中途写入失败时，检查 Actions 日志，排除问题后重新运行。

项目未显示时，先检查是否公开、未归档、属于当前账号且不是 Fork，再查看最近一次 Actions 运行。分类不合适时，调整简介、Topics 或简短的 `FOCUS_AREAS` 规则。仓库删除或可见性变化会在下次成功运行时反映；移除链接不会清除旧 Git 历史。
