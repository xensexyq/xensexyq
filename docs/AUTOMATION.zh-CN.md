# 主页自动更新

[English](AUTOMATION.md) · [简体中文](AUTOMATION.zh-CN.md) · [主页](../README.zh-CN.md)

## 1. 自动更新的内容

GitHub Actions 工作流分页读取账号的全部公开仓库，刷新 `README.md`、`README.en.md`、`README.zh-CN.md`、`README.mobile.md` 和 `README.mobile.zh-CN.md` 中的四个标记区域：

| 区域 | 内容 |
| --- | --- |
| `ABOUT` | 根据当前项目方向生成机器人学、嵌入式与机器人感知经历概要，不列项目链接或数量 |
| `PORTFOLIO` | 全部符合条件的项目、方向及仓库简介 |
| `PROJECTS` | 按创建时间排列的最新三个项目，每个项目的名称、语言与用途简介连续排成紧凑内容块，去除额外段落间距，不在名称后强制换行 |
| `TECH_STACK` | 根据公开仓库元数据、语言清单和 README 检测的技术徽章，保留类别图标和统一徽章高度，按可用宽度自然换行，不使用强制不换行的代码块 |

概览与目录排除私有、归档、Fork、其他账号所有的仓库及主页仓库。无法匹配既有分类的新方向仍会出现在**其他工具与资料**中。分类依据仓库名称、简介和 Topics，表示项目涉及的方向，不代表个人资历。一个项目采用首次匹配的分类，跨领域项目也只列一次。仓库简介在中英文版本中均保留原文。

默认主页 `README.md` 和 `README.en.md` 使用英文，中文内容保留在 `README.zh-CN.md`。默认主页使用同一表格行内的两个 50% 宽度单元格，两栏底边随内容增长自动对齐，不设置固定高度或占位空行；左侧为个人介绍与技术栈，右侧为统计卡片与最近项目，联系方式放在左栏技术栈下方。统计卡片隐藏重复标题，保留各项计数、完整等级圆环和语言分布。统计卡片使用 470 像素源宽度与 20 像素行距，为等级留足空间；语言卡片也使用 470 像素源宽度，使两张卡片的比例和显示高度一致。完整项目目录与协作说明放在下方的折叠区域。问候标题、联系方式和团队协作链接由人工维护。About Me 突出工程方式与项目经历，不作为仓库索引。技术徽章表示源码资料中的技术线索，不代表熟练程度或硬件支持已经验证。方向分类不读取 README 全文，避免把资料库引用的技术误当成作者的实现经验。

### 内容增长与窄屏布局

默认主页优先保证桌面双栏对齐，不会在窄屏自动切换为上下排列。手机和平板可点击顶部的 **📱 手机单栏**，进入 `README.mobile.md` 或 `README.mobile.zh-CN.md`；单栏版本保留语言切换和返回桌面的入口，不使用布局表格，图片随阅读宽度缩小。不依赖会被 GitHub 过滤的自定义 CSS 或脚本。

每次自动更新都生成可换行的徽章、项目简介和单列折叠目录。超长连续文本加入零宽换行字符，显示内容和链接目标保持不变；复制显示文本可能包含这些不可见字符，精确仓库地址应从链接获取。同一次更新维护全部五份文件，桌面和手机版本获得相同的生成内容。新增仓库、语言或描述无需手工重排列宽。外层布局和联系方式位于自动生成标记之外，更新器会保留它们。

验证布局时，应同时检查中英文，在 1024、1440 和 1920 像素浏览器视口下检查桌面双栏的列宽和底边；在 320、390 和 768 像素下检查手机单栏的换行、统计图和完整目录。浏览器尺寸模拟不等于手机浏览器或 GitHub App 的真机验收。GitHub 渲染规则改变后应重新检查。

## 2. 更新时机

现有定时配置在**北京时间每天 09:17**（UTC `01:17`）请求运行，GitHub 可能延迟调度。新建其他仓库不会立即触发主页工作流，会在下一次定时运行时纳入；仓库所有者也可在 Actions 中手动运行 **Update profile introduction and projects**。

`main` 上修改更新脚本、测试、工作流或任意一份 README 时也会触发。工作流先执行回归测试，再生成内容。更新后的工作流与全部 README 必须发布到默认分支后，新行为才会生效。

只需内置 `GITHUB_TOKEN` 对主页仓库的写权限，无需个人令牌、私有项目访问权限或外部 AI 服务。自动提交修改默认分支的 README，不修改账号侧栏的短 **Bio**。

## 3. 维护与故障处理

每份 README 中，各区域必须各有一对顺序正确且唯一的 `START` / `END` 标记。标记之外的内容保留。生成区域会在下次运行时覆盖；需要调整项目介绍时，应修改对应仓库的简介、Topics，或 `scripts/update-projects.cjs` 中的分类规则。

本地检查：

```bash
node --test tests/update-projects.test.cjs
```

脚本先获取输入并校验全部文档，再开始写入。源项目没有 README 可以继续，其他 API 错误会终止运行。主页标记缺失或格式错误时，不写入任何文件。相同输入生成相同内容，不产生重复提交。每个文件更新时校验原 SHA；五个文件顺序写入，并非单次原子事务。中途写入失败时，检查 Actions 日志，排除问题后重新运行。

项目未显示时，先检查是否公开、未归档、属于当前账号且不是 Fork，再查看最近一次 Actions 运行。分类不合适时，调整简介、Topics 或简短的 `FOCUS_AREAS` 规则。仓库删除或可见性变化会在下次成功运行时反映；移除链接不会清除旧 Git 历史。
